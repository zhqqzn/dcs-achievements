# Achievement #1 - “Параллельный” таймер AVR Assembler

1. Стандартная сложность - разработать программу на языке AVR Assembler под микроконтроллер Atmega8 (Arduino). 
Запускаются два параллельных таймера, параметры интервалов задаются константами TIMER1_INTERVAL и TIMER2_INTERVAL. 
При срабатывании первого таймера (через интервал TIMER1_INTERVAL) в USART выводится строка TIMER1_STR равная “ping\r\n”, при срабатывании второго строка (через интервал TIMER2_INTERVAL) TIMER2_STR равная “pong\r\n”.
2. Средняя сложность - выполнить задание стандартной сложности. 
Минимальная точность времени вывода 4 такта. 
Найти минимальную сумму значений TIMER1_INTERVAL и TIMER2_INTERVAL при которой программа выполняется корректно.
3. Высокая сложность - выполнить задание средней сложности. Разработать систему команд работающую через USART:
    * изменение значения TIMER1_INTERVAL
    * изменение значения TIMER2_INTERVAL
    * перезапуск таймеров
    * изменить строку TIMER1_STR
    * изменить строку  TIMER2_STR

При изменении значений параметров вычислять невозможность корректного исполнения программы и выводить ошибку. На время вычислений таймеры останавливать нельзя.


## 1. Установка

```sh
sudo apt update
sudo apt install -y build-essential gcc-avr binutils-avr avr-libc avrdude simavr libsimavr-dev libelf-dev pkg-config make
make check-tools
```

`avrdude` установлен для возможной работы с платой, но для запуска и проверки задания не используется. 
Сборка вспомогательных программ выполняется компилятором C; интеграционные тесты используют POSIX `sh`.

## 2. Сборка и проверки

Из каталога корневого:

```sh
make clean
make all all-task2
make test-model
make disasm disasm-task2
```

Результаты - в `build/`:

- `firmware.elf` и `firmware.hex` — полная версия с командами USART;
- `firmware-task2.elf` и `firmware-task2.hex` — вариант только с периодическим выводом;
- `firmware.lst` и `firmware-task2.lst` — листинги машинных инструкций;

`make test-model` проверяет расчётную модель расписания и работу анализаторов на корректных и заведомо ошибочных трассах. 
Это не заменяет запуск прошивки в `simavr`.

## 3. Периодический вывод и точность

Обычный запуск полной прошивки:

```sh
make sim
```

Вариант средней сложности:

```sh
make sim-task2
```

В выводе `simavr` управляющие символы возврата каретки и перевода строки (`CR/LF`) могут отображаться точками, например `ping..`. 
Это отображение непечатаемых байтов, а не часть текста сообщения.

Проверка временных характеристик варианта средней сложности:

```sh
make trace-task2
```

Команда записывает трассу в `build/udr_trace.csv` и проверяет момент записи первого байта строки в регистр `UDR` относительно расписания с допуском 4 такта процессора. 
Не запускайте измерение под GDB: остановка процессора искажает временные результаты.

Вариант средней сложности использует равные интервалы по 16384 такта и фазовый сдвиг между потоками. Их сумма — 32768 тактов (2,048 мс).

## 4. Командный интерфейс USART

Для отправки команд нужен PTY-лончер. Откройте два терминала.

В первом запустите прошивку:

```sh
make sim-pty
```

Дождитесь сообщения о виртуальном порте `/tmp/simavr-uart0` и оставьте процесс работающим.

Во втором запустите консоль:

```sh
./build/console
```

Вводите следующую команду после ответа `OK` или `ERR` на предыдущую.

| Команда | Назначение |
|---|---|
| `T1=n` | Предложить новый интервал Timer1. |
| `T2=n` | Предложить новый интервал Timer2. |
| `T=n,m` | Предложить оба интервала одной командой. |
| `S1=text` | Изменить текст потока Timer1. |
| `S2=text` | Изменить текст потока Timer2. |
| `RESTART` | Начать новое расписание с действующими параметрами. |

Интервалы задаются в тактах CPU при частоте 16 МГц: 16000 тактов соответствуют 1 мс. `S1` и `S2` принимают до 22 байтов текста; 
`CR/LF` добавляются прошивкой. Команды передаются как ASCII и завершаются символом `CR`, который консоль добавляет автоматически.

Timer2 работает в режиме CTC с делителем 128. Поэтому его интервал должен быть кратен 128 и находиться в диапазоне 128…32768 тактов. 
Интервал Timer1 хранится в 16-разрядном поле; 
фактически допустимые значения обоих таймеров также ограничены возможностью разместить в расписании обе строки и ответ `OK`/`ERR`.

Прошивка проверяет новую конфигурацию до её применения. 
Если команда неизвестна, значение некорректно или расписание не помещается в доступные временные окна, возвращается `ERR`; 
действующая конфигурация сохраняется. 
При стандартных строках по шесть байтов минимальная допустимая конфигурация с равными интервалами — `T=23680,23680`:

```text
T=23680,23680  -> OK
T=23664,23664  -> ERR
RESTART        -> OK
```

Вторая команда отклоняется, поскольку 23664 не представимо с выбранным делителем Timer2. При изменении длины строк минимальные интервалы могут увеличиться.

Не запускайте несколько консолей на одном PTY и не используйте `make sim` одновременно с `make sim-pty`.

## 5. Стресс-тест

Стресс-тест сам запускает диагностическую прошивку и подключается к виртуальному USART. Не запускайте одновременно `console`, другой PTY-симулятор или GDB.

В первом терминале:

```sh
make trace-stress
```

Дождитесь сообщения трассировщика `Start build/stress-commands in another terminal now`. Только после этого во втором терминале запустите клиент:

```sh
./build/stress-commands --repeat 20 --done-file /tmp/avr_pingpong_stress.done
```

Клиент проверяет ответы на команды, отказ недопустимых конфигураций, сохранение действующих параметров, 
замену строк во время работы и `RESTART`. По завершении клиента трассировщик останавливает симуляцию, а анализатор автоматически проверяет трассу.

Успешный запуск должен завершиться сообщениями `PASS` и клиента, и анализатора. 
Анализатор проверяет целостность строк и отклонение момента записи первого байта в `UDR` от активного расписания. 
При ошибке выше 4 тактов или при пропущенных/повреждённых данных временную проверку нельзя считать пройденной. 
Число строк и записей в трассе меняется от запуска к запуску; 
частичная строка в конце трассы может быть проигнорирована, если симуляция остановилась во время передачи.

## 6. Расчёт и ограничения

USART настроен на 8N1, `U2X=1`, `UBRR=16`. При `F_CPU=16 MHz` фактическая скорость — около 117647 бод: 136 тактов CPU на бит и 1360 тактов на кадр. Стандартная строка `ping\r\n` или `pong\r\n` занимает шесть байтов, то есть 8160 тактов передачи.

В полной версии модель расписания учитывает передачу обеих строк, слот ответа команды, подготовку ответа и защитные промежутки. 
Для стандартных строк минимальный равный период, поддерживаемый в выбранном режиме Timer2, — 23680 тактов на поток; 
сумма интервалов — 47360 тактов (2,960 мс). 
Это граница данной реализации и её модели расписания, а не универсальная оценка для других способов реализации USART или таймеров.

Четырёхтактное ограничение относится к моменту записи первого байта в `UDR`, а не к фронту стартового бита на выводе TXD. 
Результаты трассировки подтверждают поведение конкретного ELF в установленной модели `simavr`; 
они не заменяют измерений на физическом ATmega8 и не доказывают точность фронта TXD до четырёх тактов.

## 7. Структура проекта

`SOURCE_LAYOUT.txt` содержит перечень файлов и их назначение. Основные правила устройства исходников:

- `src/firmware.S` — главная единица ассемблирования, подключающая модули;
- `src/config.inc` — частота, интервалы по умолчанию, параметры USART и временные ограничения;
- `src/modules/*.inc` — данные, запуск, обработчики Timer1/Timer2, USART, расписание, команды, проверка конфигурации и очередь событий;
- `tools/*.c` — консоль, стресс-клиент, трассировщики, анализаторы и тесты;
- `tools/test_analyzers.sh` — интеграционные тесты анализаторов;
- `tools/rejected_config.gdb` — вспомогательный сценарий GDB для диагностики.

Файлы `.inc` являются логическими частями одного исходника. 
Они включаются в `firmware.S` до ассемблирования; их не нужно собирать по отдельности. 
Такое устройство сохраняет заданный порядок инструкций и позволяет проверять временные пути в едином машинном коде.

Для функциональной отладки можно запустить `SIMAVR_GDB=1 make sim-pty` и подключить `avr-gdb` к порту `1234`. 
Не используйте GDB при проверке временной точности.

## 8. Основные цели Makefile

| Цель | Назначение |
|---|---|
| `make check-tools` | Проверить наличие основных инструментов. |
| `make all` | Собрать полную прошивку и HEX-файл. |
| `make all-task2` | Собрать вариант только с периодическим выводом. |
| `make sim` / `make sim-task2` | Запустить обычный вывод `simavr`. |
| `make sim-pty` | Запустить полную прошивку с виртуальным USART-портом. |
| `make test-model` | Запустить тесты модели и анализаторов трасс. |
| `make trace-task2` | Измерить и проверить временную трассу варианта средней сложности. |
| `make trace-stress` | Проверить временную трассу при нагрузке командами. |
| `make disasm` / `make disasm-task2` | Создать листинги машинных инструкций. |
| `make clean` | Удалить результаты сборки из `build/`. |
